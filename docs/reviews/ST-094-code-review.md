# Code review – ST-094: Maintenance tasks apply to the machines a technician chooses, due at once on each
Base: main · Commits: 10 · Date: 2026-10-26

Checked and found in order: one command, two events stored together (`EVT-MaintenancePlanChanged` + `EVT-MachinesOfMaintenanceTaskChanged`, the second left out when no machine is chosen); the plan's version check; authorization before `facts` (helpers never reach the machine reads); the shared retirement lock taken per chosen machine in ID order (ADR 0010, story note); unknown / retired / doubled machines rejected in the decision, plus the `(task, machine)` unique constraint in the database; the forged non-UUID caught by `isId`; `addedAt` from the injected clock; *last done* counting only records with `recorded_at >= added_at` (HS-24, the moment itself included); the due rule (`dueAtOnce`, HS-20 on top); retired machines dropped from the count, the due list and every choice; Collection no longer publishing the category history; the journal entry with only IDs and `machineId: null` (new convention paragraph); the migration (no journal entry, the earlier of the old floor at Berlin midnight and the first counting done record, retired machines left out, records kept) with three tests from the pre-migration tag. `docs/stories/superseded-scenarios.json` lists exactly the 14 scenarios the story's definition of done names. `check-scenarios.ts` rejects stale entries (no such scenario, superseding story not in progress/done, test still there), and `check-scenarios.ts ST-094` reports 22/22. `check-language.ts` adds no warning for this diff: the "restriction"/"start date" hits only describe the old shape, in the migration and its test. Retired machines are left out of the plan count.
