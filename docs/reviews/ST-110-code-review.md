It never names the **new embedding model**, although `change.model.name` is loaded. It also posts a hidden `chatModel` taken from the address, which changes the chat model without a word on the page. Verified, no finding:
- **No key in the warning address or page.** Three independent barriers: (1) the form definition marks `key` as `secret`, so `state.values` never holds it; (2) `embeddingModelWarning` returns nothing whenever a key was typed (`keyTyped` trims like `newKeyOf`); (3) `withChosen` copies only `version`, `chatModel` and `embeddingModel`. `confirmEmbeddingModelDefinition` hard-codes `key: ""`, so the confirmation can never change the key. The test asserts the address and HTML free of the key.
- **No open redirect.** Every target is a fixed path (`EMBEDDING_MODEL_CHANGE_PAGE`, `/team/museum-settings`) plus `URLSearchParams`. „Zurück“ is built the same way (`backToAiForm`), never from a posted or queried URL.
- **A forged post cannot bypass the confirmation rule on the form.** `aiSettingsFormInput` does not read `embeddingModelConfirmed`, and the field is not in `aiSettingsFormFields`. Only `confirmEmbeddingModelAction` sets it. Posting that action directly skips seeing the warning, but needs a technician's session and Next's Server Action origin check (CSRF). This is inherent to a confirmation step and acceptable.
- **Query parameters are safe.** They reach the page only as React-escaped attribute values (hidden inputs, `defaultValue`, `href` on a fixed path). The model ID goes to OpenRouter only through `ai.model`, which refuses anything that fails `MODEL_ID` before building `/models/${id}/endpoints`, and requests never follow redirects. There is no SSRF and no path injection. A missing or garbled `version` becomes `NO_VERSION_SEEN`, so the confirmation is rejected as changed meanwhile.
- **Authorization.** The warning page calls `requireTechnician()` before reading anything or asking OpenRouter. `confirmEmbeddingModelAction` calls `requireTechnician()`, and the command's `allowedActors` still decides. The test gap for a helper is finding 5.
- **Journal and logs.** The key replacement records `changedParts: ["key-saved"]` and `keyLastFour` only. The tests assert that neither key is in the journal or in the stored row. The diff adds no logging.
- **Spoofable confirmations.** `?saved=ai-key-replaced` and `?replace=key` only show text when a readable key exists. They change nothing (same pattern as ST-104).
