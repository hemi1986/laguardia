## Resolution (implementer, 2026-10-02)

Findings of this review (#), of `/code-review` (none) and of the acceptance test (`ST-083-acceptance.md`, AT):

- **#1 major – fixed.** The eight spec headers say the account is the e2e technician each local run creates (ST-083), not `npm run setup:first-technician`.
- **#2 – fixed.** The test stubs a foreign `DATABASE_URL` and asserts the browser-test URL ignores its host and user.
- **#3 – fixed.** `next` is started through Node itself (`node_modules/next/dist/bin/next`, no `npx` layer, no shell needed on Windows); a `next dev` killed by a signal ends the wrapper with 1, not 0.
- **#4 – fixed.** The script's `E2E_PORT` is no longer exported; the config keeps its own constant (two places, both commented).
- **#6 – fixed.** `firstTechnicianRefusal` – "problem" is the glossary's word for a problem report.
- **#9 – fixed.** The conventions say a stale `.next-e2e` (like a stale `.next`) can fail the type check until it is deleted. Checked: with `.next-e2e` missing, `npm run typecheck` is green – `next typegen` points `next-env.d.ts` back to `.next` (AT 2).
- **AT 4 – fixed.** With only one of `E2E_TEAM_USERNAME` / `E2E_TEAM_PASSWORD` set, the run warns that no e2e technician is created.
- **#5 – skipped.** `src/test-support` importing the refusal texts from `scripts/` stays until a third caller needs them – then the Team module's setup provides them.
- **#7 – skipped.** The integration test checks the prepared database with plain SQL on purpose: it tests test infrastructure, and "exactly one row" is what the criterion says.
- **#8 – skipped.** `prepareE2eDatabase` takes the URL as `scripts/e2e-server.ts` does; reusing `isolatedTestDatabase` would hide that path.
- **#10 – revisit with the first browser test that uploads a photo (ST-016).** Only `DATABASE_URL` and `BETTER_AUTH_URL` are pinned for the e2e server; Blob variables from `.env.local` would reach it.
- **AT 3 – fixed with #3** (Windows).
- **AT 5 – no change.** The diff only looked like it contained ST-009 because the local `main` was behind `origin/main`.
