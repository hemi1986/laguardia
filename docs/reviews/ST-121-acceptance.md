Verdict: **accepted with remarks**

Remarks (none blocks the merge):
1. Scenario 1's test enters the question through `loadRemoveFile`/`RemoveFileView` (the page's data function and view) rather than a click on the details link; the click path is covered by the e2e `ST-038: Removal needs a confirmation` and the outline test.
2. Scenario 3 proves “it is no longer in the AI index” through `EVT-FileLeftAiIndex`; the actual entry row is asserted by ST-106's `file-removal.integration.test.ts`.
3. The outline's second example uses the title „Attract mode (Einstellungen).mp4“ instead of the scenario's „Attract mode.mp4“, so the two examples in one test stay distinguishable; the assertion is still a literal from the test's own example table, and the settings landing has no e2e counterpart.
4. The titled test for “A helper cannot remove a file” checks no-control and the command rejection; the “question page opened anyway is refused” line is asserted by an untitled e2e test in the same spec.
5. `teamMessages.removeFile.unknown` and the old comment in `removeFileRefusal` are leftovers of the machine-scoped page; they are harmless but should be cleaned up.
