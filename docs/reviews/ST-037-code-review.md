# Code review – ST-037: Attach files to a machine or machine model and find them by file category
Base: main · Commits: 9 · Date: 2026-10-18

Checked against ADR 0002 (module boundaries, command layer, journal), ADR 0006/0009 (private Blob, pending uploads, 5-minute addresses), the engineering conventions ("Files uploaded from the browser", `uploadFormAction`) and the user decisions of 2026-10-18 (1a, 2a, 3a, inline formats, `size` → `details`, check page removed). `check-language.ts`: no warning in a file of this diff (the 13 warnings are all pre-existing).

Holds: CMD-AttachFile goes through `aggregateCommand` (one transaction, `attachingActors` = any team member, EVT-FileAttached journaled in the same transaction, the title kept out of the journal). The "exactly one machine or machine model" invariant is a check constraint plus the decision. The machine model comes from facts read in the same transaction. The Team foreign key is hand-written as the conventions require. The form's own rejections run before `withUploadedContent` and keep the upload (1a). A double send does not delete attached content, because without a pending upload the call returns `content-gone` before any delete. `/team/dateien/<id>` checks the session before it reads anything, checks the ID shape, sends `Cache-Control: private, no-store` and a 303 to a 5-minute address (2a). `opensInBrowser` goes by the media type the store kept, and SVG is downloaded. Every scenario has a test with the exact title. The tests written after the UI do check their "Then": "No files yet" renders the real section and its link. The e2e tests tell inline from download by `content-disposition`, follow the file address to the 60 MB body, and check that a stranger gets a redirect to `/login` and no PDF.

Most important finding: #1 – the aggregate's own enforcement of title, file category and target is untested, because every rejection test goes through the form's early check.

## Resolution (main session, 2026-10-18)
- **#1** fixed – a command test sends CMD-AttachFile without title, file category and owner, and for an unknown machine.
- **#2** fixed – the "Title is required" test checks that the first send attached nothing, and the rejection text.
- **#3** fixed – „Die Datei muss erneut ausgewählt werden.“ only when a file was handed over; a rejection of the form's own fields without a chosen file says nothing about a file (new test).
- **#4** fixed – the machine is bound by the page (`attachFileAction.bind(null, { id, museumNumber })`) and set into the form data by the action; no hidden machine field is posted.
- **#5** fixed – `attachFileInput` without content for `refusal`.
- **#6** fixed – the aggregate's state type is `FileState`.
- **#7** fixed – `upload.clearedWith`.
- **#8** fixed – `teamMessages.fileCategories`, shared by the machine record and the form.
- Security review: no findings. Side note kept for ST-070 (script policy) / later hardening: Blob's `download=1` is not part of the signature – whoever holds an address may drop it; that only affects the Blob origin, never the app.
