### Deviation: ADR 0006 instead of editing ADR 0005
The story's last item literally offers two options: edit ADR 0005's consequences directly, or — *if the EU option turns out unavailable* — propose a follow-up ADR with an S3-compatible fallback. Neither disjunct fits exactly: the EU option **is** available, so the fallback clause doesn't literally apply, and ADR 0005 is `status: accepted`, which `CLAUDE.md` and the `protect-files.ts` hook forbid editing (only `accepted` → `superseded by ADR-NNNN` is allowed). Editing ADR 0005 as the story literally asks would have violated a hard project rule the story text didn't anticipate.

The chosen resolution – a new `proposed` ADR 0006 that records the verified setup and states it "supersedes ADR 0005 once accepted" – is the correct move under the project's own ADR rules (`.claude/skills/architect/ADR-FORMAT.md`, `protect-files.ts`) and is explicitly allowed by the spike's own framing ("a follow-up ADR is proposed"). `docs/stories/OPEN_QUESTIONS.md` row for ADR 0005 is answered, referencing ADR 0006 by name and status (`proposed`). This is consistent with the workflow: only the user accepts an ADR, which will happen alongside accepting this story. I judge the item satisfied in substance; flagging it only so the user is aware ADR 0006 remains `proposed` and ADR 0005 still shows `status: accepted` until the user acts on both.
