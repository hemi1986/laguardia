## Resolution (refactor step, 2026-10-23)

Also covers the `/code-review` pass on the same diff.

- **#1 loose implementation signature – fixed.** Each step is its own function (`withoutContent`, `photoStep`, `uploadStep`) typed with the state its overload promises; `formAction` only picks the step.
- **#2 photo rejections not exhaustive – fixed.** `rejectsThePhoto` is a `Record<PhotoError, boolean>`; a new photo error fails the type check until it is decided.
- **#3 / code-review: G8a rule written twice – skipped.** Two two-line functions over two catalogs (team, visitor); a shared helper would add a parameter for the sentence and save nothing.
- **#4 English scenario test checked other cases – fixed.** The no-photo and rejected-photo checks moved into their own test.
- **#5 / code-review: unrelated formatter changes – fixed.** The ~20 files reformatted by a too-wide `prettier --write` are back to `main`.
- **code-review: vacuous "nothing stored" check in the team browser test – fixed.** It now looks for the machine in the triage list.
- **code-review: `report-and-triage.ts` only re-exported the photo – fixed.** Removed; the forms import `teamReportProblemPhoto`.
- **code-review: selecting the step by `in` – skipped.** The overloads reject a definition with `photo: undefined` (no overload matches an input with a photo parameter and no `photo`); the definitions are written in code, never built from a request.
- **code-review: refactor on the story branch – no change.** The user decided on 2026-10-18 and again on 2026-10-23 to do architecture refactor 4 in the ST-084 branch.
- **code-review: photo sentence after rejections no resend can fix (machine not on display, retired) – no change.** The story asks for the sentence after every rejection other than of the photo itself (story review decision 3a, 2026-10-10); a change is a new decision for the ux-designer.
