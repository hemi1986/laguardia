## Verdict

**accepted with remarks.**

All seven scenarios have a real, passing test at the catalog seams (run, page data + view, runner), traceability is 7/7, the full Vitest suite is green (208 files, 1513 tests), the ST-107 browser spec still passes 2/2 at 360 px without JavaScript, and typecheck/lint are clean. The failure texts are the story's exact German texts from the catalog, all eight reasons are covered across the scenarios, the retry is one tap with the failed one's note and photos, the failed one is kept, and the broken-off / late-result / resolved / removed-file rules hold.

Non-blocking remarks for the user before merge:

1. **The page's start wiring is only code-reviewed.** The broken-off scenario tests the extracted `startWhenLeftUnfinished` and the real `aiWorkLeftUnfinished`, not `page.tsx` / `startAiWorkWhenLeftUnfinished` / `startAiWorkAfterResponse`. A cheap wrapper unit test would close it.
2. **No browser test of the failed state / „Erneut versuchen“ at 360 px or without JavaScript.** The existing AI spec covers the running/written section only.
3. **The `/security-review` is present and ready to merge** (`docs/reviews/ST-108-security-review.md`: no blocker, no major). Its S1 is the same action-seam test gap as remark 1: no test calls `retryAiAssessmentAction` with a missing session or forged `note`/`photos`/`defectId`. Its S2 is a foot-gun for ST-111: the new public `aiAssessmentsOfDefect` returns raw note/photos/requester IDs. Neither blocks this story.
4. **The requested-without-hold case** (the start call after a request failed) leaves “läuft …” refreshing with no run to pick it up; ADR 0015 accepts a broken chain waiting for the next trigger, and the security review records it as a liveness gap (not security). The story's “never finds it stuck” is not literally met. A question for ST-112 or a new story, not a blocker of the scenarios.
5. Minor test-strength gaps: the retry race / stale tap / no-note-no-photo / helper-on-suitable / AI-off-after-load cases are not tested, the “same two photos” is asserted at the input seam plus the stored count only, and the new public query's raw fields are left for ST-111 (security review S2).
