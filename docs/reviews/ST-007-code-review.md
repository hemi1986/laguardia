Not findings, but noted:
- The rule "the second one is retried with the next free number" is met by serializing registrations, not by retrying. The outcome is the same, and the conventions record it.
- The journal data of `EVT-MachineRegistered` leaves out location and serial number, as the journal convention requires (typed text).
- Module boundaries hold. Repair's schema has no import from Collection, and the foreign keys across modules are hand-written in SQL, as with `team_member`.
- Security: a helper is stopped by the page, the action and `allowedActors`. CSRF is handled by the Server Action Origin check. React escapes the typed text. No personal data is logged. Team pages only.

**ready to merge**: no blockers. The two majors (#1, #2) should still be fixed in this story first.
Most important: #2. The status history is ordered by a random UUID whenever two changes share a timestamp, which is cheap to fix now in the unmerged migration 0005 and expensive after it ships.

## Resolution (implementer, 2026-10-02)

Findings of this review (#), of `/code-review` (CR) and of the acceptance test (`ST-007-acceptance.md`, AT):

- **#2 major / CR – fixed.** `machine_status_change.position` (bigserial, migration 0006 – 0005 was already applied to the dev and preview databases, so it is not edited); the history is read in that order. New test "keeps the status history in the order it was recorded"; ordering by the random ID again fails it in 3 of 4 runs.
- **#1 major – fixed.** Both concurrency scenarios run eight registrations at once (isolated pool `max: 10`): LG-042…LG-049, resp. one winner and seven `museum-number-taken`. Without the lock both fail in 3 of 3 runs.
- **#3 / CR – fixed.** `facts` is required when `decide` takes facts (conditional type); `src/platform/command/facts-types.test.ts` proves it with `@ts-expect-error`.
- **#5 / CR – fixed.** The runner stand-in's field is `machineModelId`, so `machine-model-required` and "Bitte ein Modell wählen." describe what it checks.
- **#6 – fixed.** `withoutMachines` refuses any database but an isolated `laguardia_<name>_test`.
- **#7 – fixed (temp folders).** `migrationsUpTo` copies are removed after the reset. The working-directory dependency stays: Vitest and Playwright run from the repository root.
- **#8 – fixed.** `no-museum-number-free` marks no field.
- **CR (NaN on a malformed stored number) – fixed.** Only numbers in the LG-NNN format count for "next above the highest"; unit test in `register-machine.test.ts`.
- **AT 1 (LG-999 timeout) – fixed.** The test has a 60 s timeout.
- **AT 2 (`no-museum-number-free` untested) – fixed.** Unit tests at the decision: all given out → rejected; after LG-999 counting down (LG-500 before LG-017).
- **#4 – skipped, revisit with ST-035.** A `MuseumNumber` module (format, parsing) pays off when the correction is the second place that checks the format.
- **CR (facts for changing commands, the correction's lock) – revisit with ST-035.** CMD-CorrectMachineDetails is the first changing command with the museum number rule; it needs facts (or the same lock) on the changing branch. The stand-in has no rule of its own.
- **CR (all numbers loaded under the lock) – skipped.** At most 999 rows; registrations are rare and technician-only.
- **CR (`count(*)` on every machine update) – skipped, revisit with ST-010.** Only the stand-ins update machines today.
- **CR (museum numbers used up in `vitest --watch`) – skipped.** About 43 reruns without a reset; a normal `npm test` resets the database. The local dev database grows by a few machines per browser-test run – revisit if it ever reaches LG-999.
- **AT questions – skipped as minors:** LG-000 matches the format the user decided ("LG-" plus three digits) and stays allowed; trimming spaces around a typed museum number is intended (G13); no maximum length for location and serial number (no rule says one); a double submit without JavaScript could register twice (technician-only, rare – revisit if it happens); the `?registered=` confirmation shows again on reload and names an existing machine only; a helper opening the registration page lands on the team start page (G11: not their page).
