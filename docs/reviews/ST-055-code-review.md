**Verdict: fix blockers first.**
Most important: #1. The search rule for retired machines was put into the shared `machineOverview` read model, so the QR sticker choice now offers retired machines when searched, and ST-011's rule breaks without any test failing.

## Resolution (implement, 2026-10-25)

- **Fixed #1 (blocker):** the read model no longer decides that a search finds retired machines. `MachineOverviewQuery.retiredToo` is the caller's choice: the machine overview's page data asks for them with the filter or a search (`OverviewQuery`, `loadMachineOverview`); the sticker choice never does. ST-011's test now also searches for "013" and finds nothing. ST-008's test is back to its original assertion (a plain `machineOverview` search finds no retired machine); the read-model test of ST-055 checks `retiredToo`.
- **Fixed #2:** `MachineOverviewEntry` is a union – a retired entry carries no machine status. The technician dashboard narrows its status-filtered lists to active entries.
- **Fixed #3:** the empty-list texts live in `NothingFound` (search → no match; machine status → none with it; neither → every machine retired).
- **Fixed #5:** `aRetiredMachine` is in `e2e/fixtures.ts`.
- **Fixed #6:** the visitor page test asserts `loadReportForm` gives nothing for a retired machine (its report page answers 404).
- **Fixed #7:** the comment says what it means – only the title, no status, defects or problem reports.
- **Skipped #4:** each integration test binds its retire call once in a helper of its own, as the conventions ask; a shared test-support helper would have to import Repair's command into `src/test-support/machines.ts`. Revisit when a third test needs it.

No finding passes the follow-up hurdle.
