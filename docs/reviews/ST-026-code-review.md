**What holds:**
- Both commands go through `aggregateCommand` with their IDs from `events.yaml`, the version in `target`, pure decisions,
  no `new Date()`; journal data holds references only and matches the event data in `events.yaml`.
- Module boundaries (ADR 0002): Repair reads Team only through `@/modules/team` (`activeTeamMemberRole` in the command's
  facts, no lock – as the conventions say for another module's data); the page composes Team's and Repair's queries;
  `assigned_by`'s foreign key is hand-written.
- Authorization: the Server Actions take no acting person from the form; "only technicians assign" is in the decision
  (`assignRefusal`), and the command reads the assignee's role itself, so it does not trust the offered list (2a).
- All six scenarios have a test with the exact title at the command seam, each checking its "Then" through read models
  and `journalOf`. No tautological assertion found.
- **The extended ST-028 assertion is legitimate.** "offers resolving an open defect only to someone who may resolve it"
  pins the whole `offered` list with `toMatchObject` (arrays are compared in full), so a new action offered to a
  technician has to be added. What the test is about – resolving is offered to Tom and not to Anna – is unchanged, and the
  helper's expectation (`["log-work"]`) was not touched. Extended, not weakened.
- Decision 1a and 2a are both built and both tested (`claim-defect-command.integration.test.ts`,
  `assign-defect.integration.test.ts`, the page test's "Vorher: Anna.").
