# Code review – ST-018: Triage – record a defect, optionally changing the machine status
Base: main · Commits: 10 · Date: 2026-10-04

Checked: `git diff main...HEAD`, the context pack, ADR 0002, the engineering conventions (including the three new passages), `check-language.ts` (no warning in the changed files; the 7 warnings are older), and the ST-018 integration tests (`record-defect*`, `run*`: 10/10 green).

Architecture holds. CMD-RecordDefect is handled by the problem report (HS-16) and creates the defect through `created` in the same transaction. Collection is reached only through its `index.ts`. The inner CMD-ChangeMachineStatus runs through `context.run` as the same technician, with its own authorization check. Both events are journaled in one transaction, and the journal data has no free text. The re-decision after a failed version check is correct under READ COMMITTED: the defect inserted earlier is rolled back when the re-decision rejects. The concurrency test really runs two transactions. No blockers. The findings are about scenario "Then"s that no test checks, and a few smells.

## Resolution (main session, 2026-10-04)
- #1 – fixed: who triaged first is looked up by `withWhoTriagedFirst` (`defekt-erfassen/record-defect-rejection.ts`) and worded by `rejectionText` (`record-defect-rejection-text.ts`, pure – the client form imports only that); an integration test names "Tom" after a real triage.
- #2 – fixed: the same test file checks „LG-042 ist inzwischen ausgemustert. Es wurde nichts gespeichert.“
- #3 – fixed: a table test at the decision (`src/modules/repair/record-defect.test.ts`) – every current status × chosen status.
- Minors fixed: `triagedBy` of the page data is `triagedByName`; the two sentences in the conventions (facts read again, READ COMMITTED).
- Minors skipped: the "status changed" flag from the form data (the confirmation reads the stored status, the flag only decides whether to name it); `machineStatus`/`machineVersion` as two fields and `-1` defined twice (one in the input function, one in the command – each says what it means); `runs` iterating the one event; `reportingFacts`/`defectTitle` names; the UUID check in three places; `storedDefect` until ST-021; the comment on the foreign-key wait; a unique index on `defect.problem_report_id` (the version check and the triage CHECK already guarantee one defect per problem report); the title's maximum length – a question for the user, not decided in code; the setup note for the retirement story – noted for ST-039.
