## What holds

- **Module boundaries (ADR 0002)**: the retry lives in AI assistance and in the defect page's route folder; the action imports only the module's `index.ts` (`aiAssessmentRetryRequest`, `requestAiAssessmentCommand`, `aiDependencies`). No other module's internals are imported; Repair/Collection are not touched.
- **Command layer (ADR 0002)**: the retry is the existing **CMD-RequestAiAssessment**, run through `formAction` (the only runner), one transaction, the actor from `currentPerson()`, the command's `facts` re-checking AI on, the defect's state, the helper rule and `beingWritten` (HS-31). No new command, no version on a creating command, no journal change. The failure half stays CMD-WriteAiAssessment / EVT-AiAssessmentFailed; the broken-off reason is the `AssessmentFailureReason` from `events.yaml`.
- **Server-side input**: `aiAssessmentRetryRequest` reads the failed assessment's note and photos from the database; `retryAiAssessmentForm` has `fields: []` and `input: () => input`, so a browser cannot supply the note or the photos. The action never returns them (state is `FormState<…, never>`).
- **G11**: the retry is offered only while `data.mayRequest` – the command's own refusal (`ai off`, defect not open, helper on a defect not suitable, one being written). The request link is replaced by the retry for a failed assessment; the test proves the helper is not offered it and AI off hides it.
- **Failure texts**: all eight reasons are the exact German texts of the story table, keyed by the domain reason (`src/platform/messages/team/ai-assistance.ts:64-74`); the page shows no OpenRouter text, and the test feeds a raw answer text and proves it never reaches the page.
- **Page-start gate (HS-33, ADR 0015)**: the behaviour is unchanged and now has a testable seam (`startWhenLeftUnfinished`); the page still starts a run only while the current assessment is `requested` and `aiWorkLeftUnfinished` finds an expired hold. The test proves no start before the hold ran out, one start after it, and that the next run records *broken off* without an AI call.
- **Late result / resolved defect / removed file**: the existing hold/version check (`storeResult`, `failAiAssessmentCommand` only on `requested`) and the read model's `removed` reference are exercised by real runs and the page seam; no test waits for a background run.
- **Tests**: seven exact scenario titles (`check-scenarios` 7/7), real seams (`runAiWork` with the real kind and the injected clock/AI/storage, `formRunner`, page data function + `renderToStaticMarkup`), expected values from the story/stand-ins (not recomputed from the code), no existing test weakened.
- **Time, IDs, language**: no `new Date()`/`randomUUID()` in a decision; the run uses the injected clock; the UI word „abgebrochen“ and the failure texts match `CONTEXT.md`/the story; `„Erneut versuchen“` is the decided label.
