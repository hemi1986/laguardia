**Verdict:** fix blockers first.
Most important finding: #1. The CSP violation watch covers only the fixture's `page`, so every visitor page opened in a separate phone context, including the report form and the visitor photo upload, is never checked for policy violations.

## Resolution (implement, refactor step)
- #1 fixed: the watch is an auto fixture on the test's `context` and on every context the test opens with `browser.newContext()` (BrowserContext `console` event); proven with a throwaway probe that a violation on a second context fails the test.
- #2 fixed without a new seam: `e2e/security.spec.ts` asserts `img-src` and `connect-src` exactly – `'self'`, one `https://<id>.private.blob.vercel-storage.com` host (the same in both) and `https://vercel.com/api/blob/` – and runs on the preview too, where the host comes from `BLOB_STORE_ID`.
- #3 fixed: the public pages are opened with `page.goto`, so the watch sees them render under the preview's production policy.
- #5 fixed: the injected-script test counts only `script-src` violations.
- Skipped minors: #4 (Blob's sources stay beside the policy; moving them behind the storage seam is worth it when a second consumer needs them – revisit then), #6 (the team-page test only proves the policy reaches team pages; the preview has no account – revisit with ST-068), #7 (`X-Frame-Options: DENY` still covers framing for `/api/` and static files; they render no HTML), #8 (no nonce consumer yet – the accessor comes with the first one).
- Found on the preview by the new watch (run 40230209848): Next.js' built-in not-found page renders a `<style>` element without the nonce (`/impressum` while the museum provides no imprint). Fixed with an own root `src/app/not-found.tsx` in the visitor frame; `e2e/security.spec.ts` renders `/gibt-es-nicht` under the policy. Revisit when: Next.js' built-in error pages (`app-error`, `global-error`) have the same pattern – they only show after an unexpected server error and stay readable without their styles.
