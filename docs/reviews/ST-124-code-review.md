**Checked, no finding.**
- The command runs through `aggregateCommand` with `allowedActors: ["system"]`, a row lock instead of a version and the event in the same transaction as the hold's end.
- Only a still requested proposal is written (`not-requested`, tested).
- The journal holds the chat model, the embedding model and the cost, and none of the text (tested).
- No `new Date()` in domain logic.
- The IDs `CMD-WriteAiModelProposal` and `EVT-AiModelProposalWritten` are present.
- `makesAiWork` wakes on EVT-AiModelProposalRequested.
- The kind's order puts proposals before files.
- Only Collection's public `index.ts` is imported (allowed direction, ADR 0019 decision 1).
- `javascript:`, `data:`, `file:` and `http:` are rejected by parsing the URL (tested). React escapes all AI text. External anchors use `rel="noopener noreferrer"`.
- Logs carry only the kind, the ID and the error name.
- The bounds cover title 300, link 2000, sources 20, named documents 40 and kept documents 10.
- The migration only adds nullable columns, and the snapshot and journal are consistent.
- `check-language.ts` hits on "source" and "link" in the changed files are false positives: the glossary itself uses "link on the web" and defines a source.
- Prompt injection through fetched pages can shape the proposed links, but nothing is loaded without the technician's tick (ADR 0019 decision 3).

**Verdict:** ready to merge (no blockers) – fix finding 2 in this story and decide finding 1 before the next production deploy.
Most important: finding 1 – until ST-126, any failed write leaves the proposal *requested* for good. That blocks every new request (HS-37), and every later run pays OpenRouter for it again.
