## Remarks (test quality and follow-ups, not acceptance blockers)
- **Test isolation is fixed.** Both integration files now `DELETE FROM file` in `beforeEach`; the earlier leak (old
  files re-appearing as waiting because a fresh empty storage made them fail `not readable`) is gone.
- **New coverage added after the review:** re-index replaces the entry as a whole (new test, distinct item IDs and a
  direct DB count), corrupt image as `not readable`, direct `ai_index_item` counts on the format and unreadable
  failures, removal without an entry recording nothing, the removal-starting-during-store lock test (now filtered to
  `current_database()` and its own pids), hold ended after `file-removed`, and a broken-off file both recorded and
  left waiting while AI is off. `replaces.integration.test.ts` proves the three command-layer capabilities.
- **One full `verify.ts` run failed in its test step once; the next two runs passed with 1480 tests, and the three
  story files passed 8/8 repeated runs.** I could not reproduce the failure; if it recurs under full-suite load, the
  4 s readiness poll in `waitUntilTheRemovalWaits` (`file-removal.integration.test.ts`) is the first suspect – it
  throws when the removal has not reached the advisory wait within 200 × 20 ms.
- **Remaining code-review minors:** failure reasons are prose rather than the conventions' kebab-case enumeration
  (P1.7); text media types exclude `application/octet-stream` (P1.16); pdfjs `isEvalSupported` is still at its default
  `true` (S3); the crafted-PDF note is not yet in `docs/operations/ai-work.md` (S2); the OpenRouter-failure test has
  no direct item-row query (scenario 5).
- **wasm/ICC assets:** the test does not prove the tracing, only that page 2 renders. Check once on a deployment or
  add an asset-URL assertion; pdfjs only logs a warning when an asset is missing.

## Verdict
**accepted with remarks**

All ten scenarios have a real, passing test that drives the real entry point (`runAiWork` with `fileIndexingWork`,
`CMD-AttachFile`, the composed removal command); the review blocker and five majors are fixed; the platform
capabilities have their own seam tests; DoD 1–4 are met (the code review and its security pass exist, the branch is
pushed). The remaining items are minors and edge-case questions listed above, none of which blocks the merge.
