**Checked without a finding**
- ADR 0018 / data model *AI assessment*: CMD-WriteAiAssessment takes the file list through its input instead of `facts`. The data model documents this ("Only the system runs the command, so the list passes through its input"), `allowedActors: ["system"]` keeps it there, and the decision still enforces the reference invariant itself. It is a documented exception to *A rule that needs another module's data* in the conventions, and the conventions now describe it.
- Migration 0045: dropping the check constraint before the columns is redundant (PostgreSQL drops it with the columns) but harmless. The snapshot matches the schema. No index or foreign key on the dropped columns. Nothing is re-indexed. The fixtures include an entry of an old embedding model, as the Notes require.
- Journal: no reader outside AI assistance uses the AI index events. The cost sum reads only `data.cost`, so old entries with `machineId`/`data.machineModelId` still count (tested with a raw historic row).
- Module boundaries (ADR 0002): only Collection's public queries are imported; the page no longer composes `machineLabels`/`machineModelTitles`.
- Scenarios: all 7 ST-120 tests exist with exact titles and check their Then. "The files read when the writing begins …" changes `file_attachment` during the fake embedding call and would fail with the old in-transaction re-read. ST-109's superseded scenario is listed in `superseded-scenarios.json`.
- `check-language.ts`: no new warnings in the changed files. Story tests run green: 4 files, 39 tests.
