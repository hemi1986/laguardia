**Security pass – checked and fine:**
- **Authorization:** `requireTechnician()` runs in the action as the page check. `acceptingActors = ["technician"]` enforces it in the command. The inner runs (`CMD-CreateMachineModel`, technician; `CMD-AttachFile`, team member) are checked again by `context.run` for the same person. The actor comes only from `currentPerson()`.
- **Forged hidden fields:**
  - A non-UUID `aiModelProposalId` is `not-found`, because `isId` is checked in `load`.
  - A non-integer `version` becomes `-1`, so the result is a version conflict, or the domain reason first.
- **Forged document indices:**
  - A non-integer tick becomes `-1`, so the result is `document-unknown`.
  - An index outside the documents gives `document-unknown`. This is tested with "7".
  - Duplicates collapse in the `Map`.
- **Forged file categories:** a forged value falls back to the proposed category through `fileCategoryOf`. The posted title and category of an existing file are never read. A link's title is trimmed and falls back to the proposed one if blank. No new `href` is built from posted input. The saved page renders link titles only as text, and links are https-checked at write time (ST-124).
- **Journal content:** IDs and a count only. No title, link or typed text (finding 3 asks for a test of this).
- **Client bundle:** `accept-form.tsx` imports only types from `@/modules/ai-assistance` and `machine-model-fields`. It imports runtime code only from client-safe files: `form-parts`, `rejection-text`, the message catalog, and the new `machine-model-field-names.ts`, which was split out of `machine-model-input.ts` for exactly this reason. The choices and the file addresses are built on the server and passed as plain data. No functions cross the server/client line: catalog functions are imported in the client module, not passed as props.

**Bug pass – checked and fine:**
- **Atomicity:** the proposal row is saved first, then `runs` creates the machine model with the pre-generated ID and attaches each chosen file. Any rejection throws `Rejected` and rolls everything back. This is tested for `manufacturer-required` and for a removed file.
- **Version check:** the decision runs before the version comparison. After a rejection, the re-rendered page posts the current version.
- **jsonb `documents`:** the accepted state keeps the proposal's own values and only adds `chosen` (plus `loading: "waiting"` and the corrected title and category on links). The read model shows only the chosen ones.
- **Module boundaries (ADR 0002/0019):** AI assistance calls Collection only through `@/modules/collection` and only downstream → upstream. The new `machine_model_id` column is a bare UUID with no cross-module foreign key.
- **Scenarios:** 1, 2 and 4 are checked at the runner and render seams with literals, and the e2e covers the no-JS round trip including a kept rejection.

**Verdict:** fix blockers first
Most important finding: #1. When a proposal was saved by someone else meanwhile, the page unmounts the form and the rejection „Dieser KI-Vorschlag wurde schon gespeichert.“ is never shown. This breaks scenario 3's Then in the UI and the documented "don't swap the form" convention.
