**Verdict:** ready to merge
**Most important finding:** #1. Maintenance assumes that the first category-history entry is the creation, but the backfill silently skips models without a creation event. Document the assumption and make the migration fail loudly.

## Resolution (implementation, 2026-10-18)
- **#1 fixed** – the migration gives every machine model a first entry (left join, an epoch fallback when the journal knows no creation; tested), and `MachineForMaintenance.categoryHistory` says the first entry is the creation.
- **#2 fixed** – EVT-MachineModelCorrected journals the year too, as `events.yaml` lists it; the comment gives the reason.
- **#3 fixed** – the stale doc comment is gone.
- **#4 fixed** – the shared input is `machine-model-input.ts` with `machineModelFields`, `machineModelInput`, `MachineModelField`.
- **#5 skipped minor** – the cast narrows the runner's error string for one lookup table; typing the shared fields on each form's error union would need a generic component for no behaviour. Revisit when a third form uses `MachineModelFields`.
- **#6 fixed** – `appliesSinceCorrection` takes `Pick<MaintenanceTask, "machineCategory" | "technology">`.
- **#7 fixed** – test "a task that applies again after a second correction counts from that one".
- **#8 skipped minor** – not this story's: every form posting an aggregate ID shares it, and the fix belongs in `aggregateStore.load` (an `isId` check). Revisit at the next `/improve-codebase-architecture`.
- **#9 fixed** – the engineering conventions name the machine models form as moved to `Field` (and the `key`-before-spread rule found on the way) – **the user approves this change at acceptance**.
