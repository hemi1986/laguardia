What holds: CMD-ChangeMachineStatus goes through `aggregateCommand` (one transaction, `allowedActors` `helper`/`technician`, version check, EVT-MachineStatusChanged journalled in the same transaction). All rules and invariants sit in the decision: retired is final, helpers may only set Out of order, a reason is required, the same status is rejected. The journal carries no free text (the reason stays in the status history only). The clock and the ID generator come from the `DecisionContext`. The app imports only the Collection module's `index.ts`. The Server Action only calls the runner. The input function follows the empty-field rule. Both history proofs use a trigger that refuses UPDATE. The stand-in history test really tries to rewrite an entry, so it tests what Q13 claims.
