Checked and found sound:
- The original file name never becomes a storage name: the upload grant sends only size and type, and content names are `files/<uuid>`. It stays out of the journal (`EVT-FileAdded` has no such field).
- No CR/LF, quote, backslash or `%` reaches the quoted `filename`. `filename*` follows RFC 5987 (`'()*` are encoded) and comes after `filename` as RFC 6266 advises. The S3 header is signed into `response-content-disposition`, and a file without a name still gets plain `attachment` on download. React escapes the page.
- Forged `targets`: a malformed value is dropped (`targetOf`, Q19). A well-formed unknown ID rejects the whole command and deletes the content. Duplicates are de-duplicated in both `targetsExist` and the decision, so no unique-constraint error is possible. The pending upload is bound to the team member who sends the form (ADR 0018), so a forged content name of someone else's upload is "content-gone" and is not deleted.
- Auth: `requireTeamMember()` runs on the page and in the Server Action, and the command authorises. The client components import only types from `actions.ts` / `add-file-form.ts` and the constant from `add-file-targets.ts`, so no server-only code is bundled.
- The `ChosenFile` / `rejectionWithChosenFile` extraction is identical to the old code apart from the optional `onChosen`. The machine record's forms are unchanged, and their test still passes.
- G3: the confirmation requires the viewer's latest command to be this file's adding (`fileAddedIn`). The superseded ST-117 scenario is recorded and its test removed. AI work starts on the committed `EVT-FileAdded` (ADR 0017/0018).
- No follow-up story: no finding passes the hurdle. #1 is a fix of under an hour.

Verdict: **ready to merge** (no blockers; fix #1 and #2 in this story).
Most important finding: #1 – a long original file name with an emoji at the 200-character cut makes `contentDisposition` throw, so the file can never be opened.

## Resolution (implementer)

- **Major 1** (half character at the cut → `URIError`, 500 on opening): fixed – shortened by code points, test "never cuts a character in half".
- **Major 2** (e2e "sends its form" proved nothing): the form's runner now has a test for someone not logged in
  (`add-file-from-overview.integration.test.ts`); the upload step stops first (`content-gone`), nothing is added. The e2e keeps the
  redirect check only.
- **Minor 3, 4, 5** fixed (ending kept, direction/zero-width characters removed, unused re-export removed).
- **Skipped:** 6 (texts repeat the machine record's form on purpose – the two forms may diverge), 7 (shared mapping stays beside
  the file details that own the `machine:`/`machineModel:` value format), 8 (the literal would repeat the model title set up by
  the helper).
