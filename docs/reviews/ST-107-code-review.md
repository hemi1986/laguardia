## What holds

- **Module boundaries** (ADR 0002, ADR 0010): AI assistance reads Repair (`defectForAiAssessment`, `defectForAiAssessmentRequest`) and Collection (`machineModelOfMachineForAi`, `filesOfMachineAndModelForAi`, `filesForAiReferences`) only through their `index.ts`; Collection and Repair name no AI; the pages compose the modules (`defect-details-data.ts`, the request page). The new `photo` owner is a value of the shared photo module.
- **The command layer**: CMD-RequestAiAssessment is a creating command with `facts` read in its transaction, the set-based rule also represented by a partial unique index, and `EVT-AiAssessmentRequested`. CMD-WriteAiAssessment runs as `system` without a version, so the row is loaded `FOR UPDATE`; the decision writes only an aggregate still `requested`, so a late result after *broken off* records nothing. The write/fail pair reuses one command ID, which `events.yaml` also gives to both events.
- **Background work** (ADR 0015): the kind is added before file indexing, holds a whole AI assessment, reads/asks OpenRouter outside any transaction and stores through `piece.storeResult`; `recordBrokenOff` uses the same failure command. The run tests drive the real `runAiWork` with an injected clock, AI seam and storage; no test waits for a real run.
- **Caps** (user 2026-10-31): the text search takes 8 passages, each search 4 pages/images, merged unique and cut to 12; report photos are the 10 newest, request photos at most 5, resolved defects at most 5. Scenario *What is sent to the chat model is capped* really checks the merged list length and uniqueness, the three searches, the photo counts and the two resolved-defect edges.
- **Scope of the search and the references** are enforced in the work (finding 6 is only about *where*): only the machine's and its model's AI index entries are searched (scenario 5 proves own/model vs sibling/foreign), and only files of the machine/model are kept as references (scenario 6 proves the drop). Every reference's file title is read from Collection, removed files included.
- **Untrusted answer**: `parseAiAssessmentAnswer` reads the chat content only as JSON, requires a non-empty string summary, takes only string lists and references with a string file ID and a positive whole page, and the UI renders every field as text (React escaping). The reference file IDs are then checked against the defect's own file set before storage.
- **Key handling** in the chat seam: the key goes only into `Authorization`, the request never follows a redirect (`redirect: "manual"`) and the production base URL is fixed; failures map to domain reasons; the key/content never reaches a log or a journal. `EVT-AiAssessmentRequested`/`Written`/`Failed` carry IDs, the models and the cost only – no note, summary, causes or photo names.
- **Photos**: the request form uses the shared photos step (`PhotosField`, `withStoredPhotos`, `owner: "ai-assessments"`), the runner deletes stored photos on a rejection and the aggregate keeps the names; the page issues signed addresses to the whole team, never public addresses.
- **German texts and UI**: the section, empty text, running hint, form heading, note, photos, hint, button, report parts and the model/date/requester/cost line match the decided words; the cost uses German decimal notation. The `failed` branch is needed to keep the section truthful for *ai off* / *broken off*; ST-108 refines its wording.
- **Time and IDs**: no `new Date()`/`randomUUID()` in a decision; `requestedAt`/`changedAt` and the ID come from the command context.

## Pass 2 – security-focused

Checked and holds (no finding):
- **The OpenRouter chat seam** (`openrouter.ts:213-267`): `Authorization: Bearer` only; `redirect: "manual"`; fixed production host (`OPENROUTER_BASE_URL` ignored when `VERCEL_ENV=production`); 120 s timeout; `provider: { data_collection: "deny", zdr: true }`; no key/content in any log; a non-JSON or non-string answer becomes `""` and is *answer unusable*.
- **What leaves La Guardia**: only the defect data named by CMD-WriteAiAssessment (title/priority/hold reason, report descriptions and photos, work log text/parts, model details, resolved defects, the request note/photos, found passages/pages, and the file titles/IDs used as the reference candidates). No team member names, no reporter identity, no machine location, no files outside the machine/model. Photo names are server-generated and are only read through `readContent` in the run.
- **The structured answer** is parsed defensively (JSON object only, string summary required, string lists, positive whole pages, reference IDs filtered against the defect's own files) and rendered as React text; no `dangerouslySetInnerHTML`.
- **Key at rest/in the page**: the form never receives the key; the read model does not return it; the journal carries only the last four characters (ST-104 behaviour unchanged); finding 13 is hygiene, not a leak.
- **Photo path**: the shared photos step stores through the photo module (JPEG, metadata stripped, ≤5×600 KB), the runner deletes them on every rejection, and the page only issues signed view addresses to team members; no public address is built from an AI assessment.
- **Commands**: `requireTeamMember` before the runner, `allowedActors ["helper","technician"]`/`["system"]`, the actor from `currentPerson()`, no ID/role from the form; the defect ID from the bound argument is re-read in the facts.

Security findings: **#2** (data still sent after AI off, in the run window), **#6** (the reference invariant is below the aggregate), **#13** (unnecessary key decryption), **#18** (unbounded answer). No key leak or XSS found.

## Pass 3 – bug-focused (whole diff)

- **Concurrency / HS-31** – finding 4: the unique index is the only guarantee and its violation is unhandled. The sequential path is correct; the "two at the same moment" sentence of the story is not proved.
- **Late results / version check** – correct: `writeAiAssessmentCommand` is loaded `FOR UPDATE` (system, no version) and the decision rejects `not-requested`; `storeResult` deletes the hold only while it is still held and not expired, and a rejection still commits the hold deletion. A result after *broken off* records nothing.
- **Broken-off work** – `recordBrokenOff` fails through the same command, `failOneBrokenOff` drops the hold in the same transaction; the page trigger is missing (finding 3).
- **Transaction boundaries in the background run** – correct: no transaction while reading/sending; the store is one short transaction; `storeResult` runs `executeCommand` on the given tx (savepoint) and ignores its `{ ok: false }` so the piece ends without a second failure.
- **Caps arithmetic** – correct: 8/4 per search, 12 merged/unique, 10 report photos, 5 request photos, 5 resolved defects, 27 images in total (ST-105's measurement). Unique key `fileId:kind:page` is right for pages/images; passages of the same PDF page collapse together (see finding 9's family, harmless for the current numbers).
- **Empty/undefined paths** – `note`/`photo`/`page`/`text` are handled; a missing defect/machine model fails *answer unusable* (defensive, never reachable with the current data model); a missing photo/content is skipped – but that skipping is exactly finding 9.
- **Image rendering/reuse** – finding 8: no reuse; one read and one pdfjs document per page hit. `renderPdfPage` copies the bytes and destroys the document on every path (ST-106 P3.1's `destroy` guard is kept).
- **Model/cost** – finding 5 (model named vs used) and #14 (failure mapping). The cost is the embedding sum plus the chat usage; a failed assessment records no cost even if embeddings were paid (acceptable until ST-108 adds retry/cost display).

## Verdict

**fix blockers first** – the Client Component import of `MAX_AI_ASSESSMENT_PHOTOS` from the AI module barrel makes `next build` fail with 25 cascading errors (finding 1: pass the limit as a prop from the server page, as the work-log form does), and the seven majors should be fixed in this story as well – the most consequential are the missing page trigger for HS-33 (3), the unhandled HS-31 unique violation (4) and the chat model named vs. used (5).
Most important after the build: **finding 2** – the run keeps sending visitors' descriptions and photos after AI is turned off, which the CMD rule and the file-indexing precedent do not allow.
