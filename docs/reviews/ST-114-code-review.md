## Security pass

- **`from` origin – closed set, no open redirect:** no finding. `originOf` maps the address to `machine` / `settings` / `none`. A `machine:` value counts only when `machineOfMuseumNumber` finds a machine. That includes retired machines and reserved numbers, which resolve to the current museum number. The href is then built from the stored museum number by `teamMachinePage()` (URL-encoded). An array, a foreign URL, `//host`, or `machine:https://…` all become `none`. Every way-back href is a literal or comes from `teamMachinePage`; nothing is copied from the request. The tests cover all of these cases, and the page echoes no part of the address.
- **Helper vs. settings origin:** a helper's `from=settings` gives `none` (G11/G19). This is tested.
- **`retryFileFromDetailsAction`:** no finding.
  - `requireTeamMember()` runs before the runner, as the conventions require. The actor comes from `currentPerson()` inside `formAction`.
  - The command's `allowedActors` rejects a helper (`not-authorized`, tested: no run, journal unchanged). AI-off is rejected by the command rule (tested).
  - The bound `origin` comes back from the browser like a form field. It is only written into the query of a fixed path (`/team/dateien/<fileId>/details?…`, via `URLSearchParams`), and the page checks it again on the next load. So a forged bound value can at worst give the default way back, never a redirect elsewhere.
  - `fileId` in the landing path comes from a command that succeeded, so it is a real ID.
  - CSRF is Next.js' Server Action origin check, as everywhere else.
- **The new route `/team/dateien/[fileId]/details`:** no finding. A `page.tsx` in the child segment of the folder holding `route.ts` is allowed. The e2e test shows the old address still answers 303. The page calls `requireTeamMember()` first, then `isId`, then `fileDetails`, which excludes removed files, then `notFound()`. Nothing is logged. Staff names appear only on this team page.
