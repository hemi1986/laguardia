Most important finding: #1. The photo count has no limit before every posted photo is decoded and written to Blob, so the 5-photo rule comes too late to protect storage and the request.

## Resolution (implementer, 2026-10-25)
Together with `/code-review` (9 findings) and the security review (no finding, one side note), which found the same two bugs:
- **Major 1 fixed:** the runner refuses more than `atMost.count` photos with the command's own error before any is stored (`photos: { field, owner, atMost: { count, error } }`); CMD-LogWork checks again (new test at the command seam). The test counts the writes: none for 6 photos.
- **Also fixed (code-review #1, security side note):** a form with one photo reads only the first file of its field – before, the delegation to the photos step stored every posted file and referenced the first (new test on the visitor report form).
- **Also fixed (code-review #2):** `PhotosField` offers no picker once `MAX_WORK_LOG_PHOTOS` are chosen (passed in by the page) – the request never grows past the 4 MB body limit through the form (new browser test).
- **Minor 2 fixed:** `withStoredPhotos` has tests of its own – order, one not an image stores none, storing the 2nd of 3 fails → the stored ones are deleted, a rejected command deletes all. It now accepts and stores the photos in parallel (code-review #4).
- **Minor 3 fixed:** `rejectedBy?: string[]` is gone – `atMost.error` is typed as the command's error.
- **Minor 4 fixed:** both defect form actions share `backOnTheDefect`.
- **Minor 6 fixed:** `problem-report-photo.tsx` → `team-photos.tsx`.
- **Minor 7 fixed in part:** the label and the "full" text take the maximum from `MAX_WORK_LOG_PHOTOS`; the error text `too-many-photos` keeps its „5“ – catalog error texts are strings, and a change of the rule is a story that touches the text anyway.
- **Minor 8 fixed:** `PhotosField` frees its previews' object URLs when it unmounts.
- **Minor 9 fixed:** `photoRejectionText` has no flag any more – `photosRejectionText` for forms with several photos.
- **Repair history:** the photo addresses and the names are read with `Promise.all`, as on the defect's page (code-review #5).
- **Minor 5 skipped:** `PhotosField` and `PhotoField` stay two components – merging them changes the visitor report form of ST-016/ST-084 and its browser tests in a story about work log photos. Revisit with ST-054 (camera photo as a file), the next form with a photo.
