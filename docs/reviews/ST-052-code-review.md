## Checked, no finding

- **Module boundaries (ADR 0002).** The pages and their tests import Repair and Collection only through `index.ts`; the one deep import (`@/modules/repair/problem-report-stand-ins.test-support` in the form runner test) is the documented exception for tests. `index.ts` of Repair is unchanged; no persistence function leaves the module.
- **Command layer.** Still one command object, `CMD-ReportProblem`, one transaction. The facts add the chosen defect through `linkingFacts` – the same function, the same `FOR UPDATE` as CMD-LinkProblemReportToDefect – and only for the outcome *linked*. Journal by event type with one mapping per triage event, each exported by its own command file and used by both commands; no typed text in `data` (asserted: `{}` for resolved on the spot, `{ defectId }` for linked). Event and command IDs are those of `events.yaml`. The decision is pure – no `new Date()`, no `randomUUID()`.
- **Domain rules.** All rules of CMD-ReportProblem are in the decision: outcome mandatory for technicians only, helpers only *resolved on the spot*, visitors none, reporting's rules first, then the outcome's own decision unchanged (`note-required`, `defect-required`, `defect-of-another-machine`, `defect-not-open`). Invariants: stored with exactly one outcome; *linked* refers to an open defect of the same machine.
- **User decisions of the test plan.** (1a) a helper who sends a link gets the existing `not-authorized`, nothing stored, no photo left behind – tested at the form runner. (2a) "A defect resolved in the meantime …" is tested at the form runner with the literal rejection text.
- **The refactor commit `9e65bac`.** `DefectFields` and `defectInput` moved verbatim (only a comment changed; `wholeNumber` and `NO_VERSION_SEEN` became exports). ST-018's form imports them from the new place; its fields, its input function's result and its rejection text are unchanged – no behaviour change. ST-023 review #15 is taken: the choice page's texts are in `reportAndTriage`, the shared pieces beside the routes.
- **Security.** Server Actions only, `requireTeamMember()` before the runner, authorization in the command; the helper is turned away from the link page and refused by the command; IDs from the address are validated (`isId`) and scoped to the machine before anything is shown; museum numbers URL-encoded in every redirect; nothing new on visitor pages; nothing logged.
- **Language.** *Note* for the text of *resolved on the spot* follows `events.yaml` and ST-019; whether the glossary allows it is the open question of 2026-10-10 in `OPEN_QUESTIONS.md` (ST-019, ST-052), still unanswered – this story adds `note` in `TriageInTheSameStep` and one form field, and should follow whatever is decided there. UI texts are the story's wording.
- **Scenario tests.** 13 titled tests; each checks its "Then". Two scenarios are split over two tests, as in ST-023: "Helpers cannot link …" (the titled form runner test is the "But", the untitled browser test the redirect – the titled test says so in a comment). "Not stored" in the two browser rejections is checked where a stored problem report would show (triage list for the helper, the defect's page for the link) – not vacuous.
- **Scope.** Nothing beyond the story; reopening on linking (ST-053) is not touched; the photo marker stays out of the photo runner (ST-084, on purpose).
- **The conventions paragraph** describes the code as it is. It is new text in the conventions and needs the user's approval like ST-023's.

## Resolution (implementation, 2026-10-11)

- **#1 fixed:** `triaged-when-reporting.integration.test.ts` tests the loader at its own seam: each outcome's confirmation, and nothing for an ID of another machine, a problem report of this machine under the wrong parameter, an unknown or malformed ID, or a parameter given twice.
- **#2 fixed:** `melden/report-and-triage-action.ts` is the one Server Action body of the three forms (access check, machine by museum number, runner with photo, landing, photo marker); each `actions.ts` only names its fields, its input function and what the machine record confirms. The composition of runner and `withPhotoToChooseAgain` now exists once – still without a test of its own, because it reads the request's session (known gap, as in ST-023).
- **#3 fixed:** the rule "who may choose which outcome" is written once and read from the commands' own actor lists (`recordingActors`, `linkingActors`, `resolvingActors`); `triage()` has no `not-authorized` branch any more – a call for someone who may not choose the outcome throws.
- **#4 fixed:** a kept link form whose defects are all gone says „LG-042 hat keine offenen Defekte.“ in the choice (G7).
- **#5 partly fixed:** the loader checks one address parameter at a time, no precedence between them. **Skipped:** the triage list's loaders stay separate – they land on another page and name the machine from the problem report; merging them is for `/improve-codebase-architecture`.
- **#6 skipped:** the three forms and pages share the report section, the rejection text and the action; the remaining frame (heading, machine line, back link) is about ten lines each. **Revisit** when a fourth such page appears.
- **#7 fixed:** `isAboutDescription` – also used by the plain report form and the record-defect form; no new language warning.
- **#8 fixed:** „Defekt“ and „Direkt behoben“ as section headings come from `terms`.
- **#9 fixed:** the "no open defects" sentence stands where the button would be – before the other outcomes.
- **#10 fixed:** the photo test checks that the stored problem report refers to the stored photo. **Skipped:** the resolve form's runner tests stay in the link form's test file – they share its whole arrangement.
- **#11 skipped:** the copied e2e arrangement helpers are a line for the next architecture scan (17 specs).
- **Known gaps stay:** "stays at the form" after `defect-not-open` (decision 2a) and `retired && !state` have no browser test; no concurrency test for a link in the same step (the lock is the one proven for CMD-LinkProblemReportToDefect).
