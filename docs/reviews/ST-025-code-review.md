## Checked, no finding

- **Command layer (ADR 0002).** `aggregateCommand`, `CMD-ClaimDefect` / `EVT-DefectClaimed` / `AGG-Defect` by ID, the version in `target`, the decision pure (clock and actor from the context), journal data holds references only, `machineId` set. The Server Action only calls the runner after `requireTeamMember()`; the acting person comes from the session.
- **Domain rules.** Not open (resolved and closed on retirement), helpers only on defects suitable for helpers, at most one claimant (one pair of columns), one's own claim again rejected without renewing `claimedAt` (decision 3a, tested at the command seam with a later clock), concurrent claim a `version-conflict` and no takeover – all in the decision or the layer, none only in the UI. The order of rejections (state first) is pinned by the table test, whose expected values are literals.
- **Module boundaries.** The pages compose Repair's and Team's public queries; the foreign key to `team_member` is hand-written in the migration, `schema.ts` imports nothing of Team.
- **Migration and room for ST-026 / "Assigned by".** Two nullable columns, `CHECK` both-or-none, `ON DELETE RESTRICT` – hand-written like the earlier checks (0009–0013). `toRow` writes `null`, so a decision that drops the claim (release in ST-026, resolving in ST-028) empties both columns; `toState` builds the claim only from both. "Assigned by" is one more nullable column plus an extension of the check, and `toRow`'s `null` default clears it on a later takeover – nothing here is in the way.
- **Confirmation driven by `?claimed=1`.** The same pattern as `?statusChanged=1`, `?problemReported=1`. The address alone says nothing: the view also requires that the claim is the viewer's, and the name comes from stored data – tested ("confirms nothing nobody did"). As with the older confirmations it shows again when the claimant reopens that address.
- **Security.** No visitor page touched; no team member name or ID leaves the team pages; React escapes the title and the names; nothing is logged.
- **Language.** Claim / claimant / take over / suitable for helpers as in `CONTEXT.md`, German texts use „Übernehmen“; no `_Avoid_` word. "Stale claim" is not anticipated anywhere (out of scope, ST-048).
- **Scenarios.** All six have a test with the exact title whose assertions check the "Then": the claim through RM-OpenDefects and the journal, the rejections with the unchanged claimant and journal, the filter through the page's data and rendered list, the first scenario in the browser including the list as another team member sees it. Like the other team browser tests it runs locally only (no account on the preview before ST-068).
- **Scope.** Nothing of ST-026 or ST-048 was built.

## Verdict

ready to merge after the two majors – no blocker: no ADR, domain rule, security rule or scenario is violated.

## Resolution (implementation, 2026-10-11)

- **#1 fixed (domain-architect):** `events.yaml` lists "Taken over from (optional)" on EVT-DefectClaimed; the data model says it is event data kept in the journal, not part of the Claim value object.
- **#2 fixed:** `src/test-support/held-row.ts` – `whileHoldingRow` counts only the sessions blocked by its own holding transaction (directly or behind one another, `pg_blocking_pids`) and lets go in a `finally`. All three concurrency tests use it (claim, record defect, link); their local copies are gone. Each ran three times green beside the others. The claim test's comment says that the order relies on PostgreSQL's lock queue.
- **#3 fixed:** `takenOverFrom` sits next to the journal mapping in `claim-defect-command.ts` and is read only for the claimant just back from claiming (`justClaimed`), not on every load of the page. The conventions paragraph is rewritten to what is built – **for the user to approve**.
- **#4 fixed:** `claimRefusal(defect, actor)` is the one rule; the decision applies it and the page's data function asks it. No copy in the page.
- **#5 fixed:** `src/app/(team)/team/claimant.ts` beside the routes, like `reporter.ts`; a claimant whose account is gone is „unbekannt“.
- **#6 fixed:** one shape of `viewer` (`{ id, role }`) for the list and the defect's page. It stays optional: without a viewer nothing is offered and "claimed by me" matches nothing.
- **#7 fixed:** the command's result is the defect's ID only; the action lands on the defect the command names.
- **#8 changed, for the user to confirm:** `not-suitable-for-helpers` reads „Dieser Defekt ist nicht für Helfer:innen geeignet.“ – it fits assigning (ST-026) too.
- **#9 fixed:** the version is read with `wholeNumber` / `NO_VERSION_SEEN` from `defect-input.ts`.
- **#10 skipped:** the command tests keep `storedDefect` for the stored claim (incl. `claimedAt`); the read models are asserted in the page tests.
- **#11 fixed:** the filter test combines "claimed by me" with a filter that matches one of hers and with one that matches nothing, and checks the empty state of the filter alone.
- **#12 fixed:** copy leftovers removed from `e2e/claim-defect.spec.ts`.
- **#13 fixed:** the browser test "a claim made meanwhile…" (acceptance minor) walks conflict → takeover and expects no rejection left after it.
