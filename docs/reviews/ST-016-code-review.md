**Checks requested by the main session:**
- `src/photo/browser.ts` as a second public entry is **justified**. `index.ts` pulls in `server-only` through `store-photo.ts`, so a client component cannot import it. Splitting the module into a server half and a browser half, both enforced by lint, keeps one module with two entries rather than leaking internals. Only trim its exports (#11).
- The reworded ST-013 test "No contact data is asked for" **still guards** against contact fields. Every text, email, tel and other non-file input, every `textarea` and every `select` is still counted (exactly one, `description`), and every file input must be unnamed or named `photo`.
- The 2 MB server guard shows "höchstens 20 MB" / "at most 20 MB" in both visitor catalogs and the team catalog, and `messages.test.ts` pins it. The PLACEHOLDER photo notice is marked in `visitor.de` and `visitor.en`, as decided.
- Security: the visitor machine page's data holds no photo reference. The test checks this and checks that no `<img>` is rendered. The journal entry of `EVT-ProblemReported` carries no photo. Rejected forms echo only the declared fields, never the photo. View addresses are issued only by team page data, after `requireTeamMember`.
- No finding passes the follow-up hurdle. #13 belongs to ST-020; rate limits for anonymous photo uploads stay with ST-014, which the user has deferred.

Verdict: **ready to merge** (no blockers). Fix the two majors in this story first.
Most important: commit the working tree's `deleteQuietly` fix (#1). Without it, a failed Blob delete after a rejected report throws away the visitor's typed description.
