## The three questions

**1. A save without a change – is anything lost?** Yes, one thing: the only cheap way to start a run on purpose. No data and no work are lost, and nothing fails.
- **Where it mattered:** work that waits with no hold behind it, so opening a page (HS-33, HS-35) does not start anything. That is a failed self-call of the chain, and the ops doc's own case: `AI_WORK_SECRET` missing, then set and redeployed.
- **Not affected:** a run that was cut off. Its hold runs out, and opening „Einstellungen“ starts the next run.
- **What remains:** typing the key again (`newKeyOf` does not compare it with the saved key, so it always journals `key-saved`), changing the chat model, attaching a file, a new AI assessment request, or „Erneut versuchen“ on a failed file. All work, but none is obvious, and each changes something.
- **Assessment:** acceptable. The old comment called this start merely „harmless“, so it was never a designed feature. The new behaviour is also easier to explain. It still needs the doc changes in finding 4 and the user's decision.

**2. Importing the module into `formAction`.** The direction stands; the size of the import does not (finding 1).
- **Boundary:** app → module → platform is what `eslint.config.mjs` asks for. The platform gets only a generic callback, and `ai-work-events.ts` imports only a type from it.
- **Import cycle:** none. `form-action` → `ai-work` → the module and `start-ai-work`; nothing there imports `form-action` or `src/app`.
- **Client bundle:** not affected. Client components import `form-action` as `import type`, and both files are `server-only`.
- **Real cost:** failure reach and function size more than the 78 ms.

**3. The changed tests.**
- **`start` counts removed:** they counted the test's own stand-in, and `true`/`false` already said the same, so deleting `startWhenLeftUnfinished` (a shallow pass-through) lost nothing there. The page's `if … start` has no test, but neither had the page's `aiWorkStarter()` before. A one-line `if` in a page is acceptable.
- **One exception:** the AI-off case did lose its check (finding 3).
- **`retry()`'s `starts`:** stronger than before. It used to count the test's own `onSuccess`, and now the real journaled events go through `makesAiWork`.

## Looked at and found in order
- **`after()` timing:** it is called in the same place relative to `redirect`, and Next.js runs it even after a `redirect` or an error (`after.md:54`). It runs after the response, so after the commit and after the content step. If `onSuccess` or `deleteWhatItRemoved` fails after a commit, a run now starts where none did before. That is better: the work exists.
- **Runner steps:** `withoutContent`, photos, logo, upload, many and each all pass `afterCommit` through. `Omit<CommandDependencies, "actor">` carries it by type.
- **Listed events:** `EVT-FileAttached`, `EVT-AiAssessmentRequested`, `EVT-FileIndexingRetried` and `EVT-AiSettingsChanged` are each produced by one decision, and each command is run only by the actions that had a hand call. No policy and no `context.run` emits them.
- **Runs:** they pass no `afterCommit`, so there is no self-trigger; the chain stays the route's own.
- **`removeKey`:** `changedParts` is exactly `["key-removed"]`, and no start, as before. A key removed in a save does not exist.
- **Chat model change:** started before and starts now. Neutral, and covered by the unit table.
- **Other commands with empty events:** `mayChangeNothing` is only on the AI settings and on two Collection commands whose events are not listed. The request and retry commands always journal when they succeed.
- **Callers outside `formAction`:** `formRunner` has one production caller. `executeCommand` outside the runner is only the AI work.
- **Language:** `check-language.ts` reports 115 warnings. Those I sampled in the changed files are the `ai` / `hit` substring matches already found across this code; no new term.
- **Not run:** browser specs (as asked), and no new build.

ready to merge – no blocker; findings 1 to 5 are majors that belong in this branch before the user merges.
Most important: finding 1, because `formAction` makes the visitor's report form depend on the native canvas binary, and a separate public entry for `makesAiWork` removes that.
