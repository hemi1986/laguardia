## Resolution (2026-10-09, /implement step 6)

- **#1 fixed:** the command test is now titled "refuses "machine retired" by hand like a missing reason, and accepts the three reasons a person may choose". The scenario title stays on the browser test only.
- **#3 fixed:**
  - `alreadyTriagedBy` lives once, under `triage`; `toTriage` became the existing `triage.back` (same text).
  - One `triageRejectionText` (`[problemReportId]/triage-rejection-text.ts`) serves all three triage forms. Record defect keeps only its own *machine retired meanwhile* case.
  - One `loadTriagedConfirmation(db, clock, id, outcome)` replaces `loadResolvedOnTheSpot` and `loadDismissed`.
  - The browser run caught a regression on the way: the shared rejection text first lived in `who-triaged-first.ts`, which pulls server-only code into the client forms. It now has its own file that imports only the catalog.
- **#4 fixed:** `PhotoRunnerDependencies` is removed; the `storage` comment on `RunnerDependencies` covers both uses.
- **#6 fixed:** `dismiss.notYet` → `dismiss.questionBack`.
- **#2 skipped:** revisit when a second caller of a photo-removing command appears; then the runner should pick up a removed photo from the result itself.
- **#5 skipped:** keeping the list entry at `string` would need a separate result type for `problemReportForTriage` and for the page's `TriageListItem`, plus a narrowing in `triageList`. That is more types than it buys, while the page and the list share one entry today. The list's view renders an absent description as nothing.
- **#7 no change:** photo deletion is tested at the form runner with `memoryStorage`. The spam question with a real photo is checked on the preview, where the Blob store exists.

`/code-review` (separate run): one low finding. „Direkt behoben“ and „Defekt erfassen“ showed an empty paragraph for a problem report dismissed as spam. Fixed in aca414e: a shared `ProblemReportDescription` is used on all four pages. `/security-review`: no findings.
