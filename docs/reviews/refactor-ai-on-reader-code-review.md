# Code review – refactor-ai-on-reader (candidate 1, architecture review 2026-11-01)
Base: main · Commits: 1 · Date: 2026-11-02

No story: a behaviour-neutral refactoring. `aiState(db, deps)` replaces `aiIndexingSettings` and `aiAssessmentSettings`; the form „KI“ reads the same answer through the private `aiStateOf`. No test file changed. Verify and the browser specs for AI settings and assessments passed (caller); this review did not rerun them. This review compared the code by reading it, and ran `check-language.ts`.

**No behaviour difference found.** Every reader was compared with its version on main:

- **The on/off condition is the same expression.** Old: `!!key && !!chatModel && !!embeddingModel`. New: `key && chatModel && embeddingModel`. An empty string counts as missing in both.
- **Readers that acted while off:** only `embeddingModelChange` used the models without checking `aiOn`, and it now reads `savedAiModels`. Every other reader (`waiting`, `isWaiting`, `work`, `recordBrokenOff`, the overview, `filesTheAiCannotRead`, the retry facts, the page, the command, `searchWithTheDefect`, `embedItems`) checked `aiOn` first, so the old states "`aiOn` true but a field missing" could not occur. The removed `!key` and `!embeddingModel` checks were dead code.
- **`embeddingModelChange`:** it no longer calls `encryptionKey()` or decrypts. This is not observable: `environmentEncryptionKey`, `encryptionKeyOf` and `decryptKey` do not throw (`decryptKey` catches the crypto errors), and the old code ignored the decrypted key.
- **Order of refusals:** `requestRefusal` has the same four checks in the same order as both old copies. The decision's old helper check had no `!person`, but the actor is always present there, so that branch is unreachable from the decision. Too many photos is still checked after the refusals. The page's old `requestRefusal` had the same `!viewer` branch.
- **Off with a usable key (the form):** `keyUsable = !missing.includes("key")` equals the old `!!usableKey(...)`. On has `missing = []`, so it is usable. Off without "key" in `missing` still shows `keyLastFour`. Covered by `ai-settings.integration.test.ts:145` (key alone: AI off, „Gespeicherter Schlüssel: …a1b2“).
- **Unreadable key:** `keyUnreadable` is `!!state.key && !key` as before. The form's `!now.on && now.keyUnreadable` gives false while on, which the old expression also gave. `keyLastFour` stays hidden. `missing` still starts with "key". Covered for the form and the page by `ai-settings-change.integration.test.ts:252-290`.
- **`tx` versus `db`:** every reader keeps its handle: `tx` in `isWaiting`, `recordBrokenOff`, the retry facts and the request facts, `db` or `context.db` in `waiting`, `work`, the per-request reads and the read models. The request facts still read in parallel on the handle they get, as on main. The page's parallel read is now nested, with the same reads. The number of settings reads per work piece is unchanged.
- **Key exposure:** `aiState`, `AiState` and `savedAiModels` are not exported from `index.ts`. No facts carry the key. `AiState` reaches no read model's return value. `embeddingModelChange` now holds less secret material than before.
- **`aiSettingsFacts`** still uses `usableKey` directly. That is right: the test embedding needs the saved key while AI is off, and it does not answer "is AI on".

**The deliberate decisions hold:**

- **`requestRefusal` next to the decision instead of a dry run:** right. A dry run would need `clock`, `newId` and a `teamMemberId` the page may not have, and it would also apply the photo limit the page must not. It follows `claimRefusal` (conventions line 243) apart from #3. `facts.chatModel!` loses the compiler's narrowing, but the comment names the reason, the rule sits a few lines above, and `ai-assessment.integration.test.ts:275` fails if the check goes. No better shape is worth the cost: re-checking would add a second, unreachable path.
- **Decision facts without `aiOn`:** behaviour-neutral. Removing the key leaves the models saved, so this is the case that could differ. `chatModel` and `embeddingModel` are undefined then, and the tests at `ai-assessment.integration.test.ts:275` and `ai-index-overview.integration.test.ts:345` cover it through the real commands.
- **`requestAiAssessmentFacts` shared by command and read model:** no cycle; see #4 for the import direction.
- **`savedAiModels`:** the right reader, because `aiState` would answer `no-change` while off. See #1 for the missing test.

**Conventions text:** accurate against the code. `check-language.ts` adds only the `ai` warnings of #2.
