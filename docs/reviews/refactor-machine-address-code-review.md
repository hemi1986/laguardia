# Code review – refactor-machine-address: every page of a machine leads from a reserved museum number to the same page under the current one
Base: main · Commits: 1 · Date: 2026-10-30

Refactoring branch without a story (architecture review 2026-10-30, candidate K1, behaviour change accepted by the user). Graded with the follow-up hurdle: none of the findings is a security or data-loss risk, so none becomes a story.

Things I checked that hold:
- **Coverage.** All 18 `page.tsx` under `src/app/(team)/team/machines/[museumNumber]/` and `src/app/m/[museumNumber]/` call `museumNumberOfPage`. Every `sub` matches its route folder. No other `decodeURIComponent` remains in `src/app/`, and `machineOfMuseumNumber` is called only by the new module. There is no `layout.tsx`, `route.ts` or `generateMetadata` under these segments that reads the museum number.
- **Order of the access checks.** On every team page `requireTeamMember`/`requireTechnician` runs before `museumNumberOfPage`. So a logged-out visitor or a helper on a technician page never gets a redirect that shows the current museum number. `defekt-erfassen` and `mit-defekt-verknuepfen` check the role after the redirect (helper: reserved address, then current address, then `/melden`), which is fine.
- **Visitor pages.** `/m/<reserved>` already redirected to the current museum number before this change. `/m/<reserved>/melden` now shows the same public fact and nothing new. A logged-in team member on `/m/<reserved>` still needs two hops, as before (the order is now redirect, then team redirect).
- **Query and open redirect.** The target is always a literal `/team/machines/` or `/m/` plus `encodeURIComponent` of the museum number from the database. The query is rebuilt with `URLSearchParams`: array values repeat, `undefined` is dropped, everything is encoded. No path segment comes from the request without encoding, so an open redirect is impossible.
- **Server Actions.** Every bound action (`.bind(null, museumNumber)` / `machine.museumNumber`) is bound on the render that runs after the redirect, so it carries the current museum number.
- **Tests.** The table test sits at the read-model seam: real PostgreSQL, data set up through `executeCommand`, literal expected addresses, current/unknown/malformed rows included. It passes (10/10). The browser test covers four team sub-pages (one with a query) and the visitor report form.

- **#6 fixed** – the file ID goes into the redirect as it came from the address.
- **#7 fixed** – the browser test says `reserved`.
- **#8 fixed** – the unrelated formatting change is reverted.
- **#2, #5 skipped** – revisit when a machine page is renamed or a new one added: type the sub-page names against the route names, and move the hand-written machine addresses onto `teamMachinePage`.
- **#3 accepted** – one primary-key join per page load, the price of one rule for every page.
- **#9** – no action (as before).
