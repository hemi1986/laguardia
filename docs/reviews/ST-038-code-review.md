# Code review – ST-038: Remove a file
Base: main · Commits: 6 · Date: 2026-10-25

The four decisions under review hold up. CMD-RemoveFile is an ordinary `aggregateCommand` on AGG-File: it saves at the version the technician saw (HS-16), only technicians may run it (`allowedActors` plus `removeFileRefusal`, which the decision and the machine record both ask, G11), and EVT-FileRemoved is projected through Collection's event catalogue with references only. The record is kept, with a both-or-neither CHECK and a foreign key on `removed_by` in migration 0031. The content is deleted after the commit through the shared `deleteRemovedContent`, which logs only the stored name (ADR 0009). `filesOfMachine` and `fileToOpen` leave removed files out. The confirmation follows the G3 rule (`lastCommandBy` plus `fileRemovedIn`, and only for a file of this page). The question page matches G10/G10b word for word, and „Zurück“ is a plain link. `check-language.ts` reports nothing in the new code. The three ST-038 integration test files pass (10 tests). All four scenario tests check their "Then". The making of the ST-037 locators `exact: true` is correct and needed.

**Verdict:** ready to merge (after the main session decides on finding 1 – no blockers).
Most important finding: #1 – deleting a removed file's content still depends on each form wiring `removesContent`. Now that a second caller exists, the command should declare the content it removes, and the runner should delete it for every command.
