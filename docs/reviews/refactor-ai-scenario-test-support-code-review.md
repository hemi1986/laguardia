# Code review – refactor-ai-scenario-test-support (candidate 3, architecture review 2026-11-01)
Base: main · Commits: 1 · Date: 2026-11-01

No story: a tests-only refactoring. It adds `src/modules/ai-assistance/ai-scenario.test-support.ts` (`aiScenario`) and `src/test-support/html.ts`, which replace the helpers copied across 11 integration tests (ST-109 code review #5, ST-110 code review #11). It also adds the conventions bullet "AI scenarios". No production code changed. Gate green (caller).

**Nothing checks less than before.** Every migrated helper was compared with the one it replaces:
- **Test and assertion counts** are the same in all 11 files (`it(` 7/4/5/10/8/13/2/7/5/14/4, `expect` counts identical).
- **Accepted keys:** `openRouter()` = `memoryAi({ acceptedKeys: [SCENARIO_KEY], ...settings })`, which is the old `anAi`/`ai`. `SCENARIO_KEY` is the same literal. Where a file accepted `OTHER_KEY` too, the explicit `acceptedKeys` still overrides the default (`ai-settings*.integration.test.ts`).
- **fileCategory:** the default is `"manual"`. `ai-index-overview` and `file-indexing` pass `"other"`, as before. Every other file used `"manual"`.
- **contentType and size:** each caller passes the same content type it used before. The size is still `bytes.length`. For `attachedAndIndexed` in the app `ai-settings-change` test, 1000 bytes gives size 1000, as before (see #5).
- **Clock:** the scenario clock is the one each file used (`fixedClock(NOW)`, a `steppingClock`, or `clock`). `earlier-ai-assessments` keeps its per-request clock through `at: fixedClock(at)`. Its attach and settings save still use `fixedClock(NOW)`.
- **Actor:** Tom in every file. `ai-assessment.integration` keeps the helper actor through `by: actor`.
- **Encryption key:** there was one `randomBytes(32)` per file and now there is one per scenario, with one scenario per file. The tests that need a different environment (`ai-settings*.integration.test.ts` L416/L278) still build one themselves.
- **`aPhoto`:** copying `aJpeg()` into a buffer with no extra length gives the same bytes as `Uint8Array.from(aJpeg())`.
- **Run:** `budgetSeconds` is 250 and `continueWork` is a no-op, unless the caller overrides them. `file-indexing` keeps its counting `continueWork`.
- **`file-indexing` `saveAiSettings`:** it lost its `key` parameter. No caller on main passed it (only `ai` and `embeddingModel`).
- **`embeddingModelConfirmed: true` in `turnAiOn` is harmless.** `change-ai-settings.ts:150` rejects only when the embedding model *changes* and one is already saved. Several files did not send the flag before (failure, ai-assessment, earlier, overview, app settings-change, request, writing, removal). All of them save `geminiEmbedding`, either onto empty settings (first model, no warning) or onto the same model (no change, no event). So the flag was never consulted. The flag is not part of `EVT-AiSettingsChanged`, so the journal is unchanged. The only caller that changes the model (`file-indexing` L264) sent the flag before too.

**Discrimination holds.** `"checkKey" in settings` separates `AiSeam` (it requires `checkKey`) from `MemoryAiSettings` (no such member). `"encryptionKey" in given` separates `AiDependencies` from the seam (`AiSeam` has no `encryptionKey`). Both are sound today, but see #1.

**Boundaries:** `ai-scenario.test-support.ts` imports `attachFileCommand` through Collection's `index.ts` and the platform through its public paths. App tests importing a module's `*.test-support.ts` follow existing practice (`ai-seam.test-support`, `ai-assessment.test-support`). `src/test-support/html.ts` sits where test-only helpers belong (ST-067). `check-language.ts` reports no warning in the changed files.

Verdict: ready to merge
Most important: nothing blocks. Every migrated helper uses the same keys, category, content type, clock and actor as before, and test and assertion counts are unchanged. The `embeddingModelConfirmed: true` that `turnAiOn` now always sends is never consulted for any caller that did not send it before. The finding most worth acting on is #1: the overloaded `ai(…)`/`with` parameters are told apart by member names of other types.
