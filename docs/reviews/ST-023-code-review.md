## Checked, no finding

- **Module boundaries (ADR 0002).** Repair imports Collection only through `@/modules/collection` (`changeMachineStatusCommand`, `machineForReporting`); the machine status changes only through CMD-ChangeMachineStatus via `runs`, as the same technician, in the same transaction, with that command's own authorization check. The pages import both modules through `index.ts`.
- **Command layer.** One transaction; journal entries EVT-ProblemReported → EVT-DefectRecorded → EVT-MachineStatusChanged in that order, all by the technician (asserted); no free text in the journal; IDs from `events.yaml`; no `new Date()` / `randomUUID()` in the decision.
- **`not-authorized` returned by the decision** (user decision 3a): acceptable. The conventions place role rules beyond `allowedActors` in the decision, the code is already part of every command's error type, and the check runs before anything else, as the layer's own does.
- **Invariants.** The defect refers to the new problem report and its machine; the problem report is stored with exactly one outcome; a technician's problem report cannot be stored untriaged through either typed name of the command.
- **Security.** Server Actions only; the page's access check before the runner; museum number URL-encoded in every redirect; the defect ID in the address is validated and scoped to the machine; no personal data in logs or the journal; nothing internal in the visitor texts.
- **Language.** `check-language.ts` reports nothing in files of this story; team texts are the story's own wording.
- **Rearranged tests (user decision 1a).** Four integration test files and six browser specs: only the arrangement changed (reporter is a visitor or helper), every assertion is unchanged. `current-person.integration.test.ts` now proves the technician's and the promoted helper's role on CMD-CreateMachineModel – a technicians-only command, so not weaker.
- **Extraction of `DefectFields`.** Moved verbatim from ST-018's form; behaviour unchanged.

## Known gaps (user decision 2a – not findings)

- The redirect in `melden/actions.ts` on `triage-required` (to `/melden?triageRequired=1`) has no automated test; scenario 3 is tested at the form runner plus the rendered `TriageChoice`.
- The form's `machine.retired && !state` behaviour has no automated test; scenario 16 is tested at the form runner plus the rejection text.
- Same kind: `reportAndRecordDefectAction` composing the runner with `withPhotoToChooseAgain` is re-assembled by hand in the integration test, so the action's own last line is covered by no test.

**Verdict: ready to merge** once the three majors are settled in this story – no blocker; no finding passes the follow-up hurdle.
