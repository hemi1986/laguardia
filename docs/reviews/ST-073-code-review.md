# Code review – ST-073: Server Action runner – the one way from a form to a command
Base: main · Commits: 11 · Date: 2026-09-29

Checked: `git diff main...HEAD`, the context pack, ADR 0002, `CONTEXT.md`, the engineering conventions including this story's update. `tsc --noEmit` and `eslint src e2e` are clean, `check-language.ts` passes, and the unit and runner integration tests (`src/platform`, `src/app/_actions`, `src/app/report-problem-input.test.ts`) are green locally. The e2e suite was not re-run.

What holds: `formAction` has no actor parameter (backed by `@ts-expect-error` cases). The acting person comes only from `currentPerson()`, which delegates to the ST-004 session lookup. Lint keeps `executeCommand` and `formRunner` out of `src/app/` outside `_actions/`, and that rule is shown to fail and to pass in `module-boundaries.test.ts`. The rejection returns `{ error, values }` and echoes only the declared fields. The cast `actor as ActorOf<Allowed>` in `aggregate.ts:153` is sound because `executeCommand` checks `allowedActors` before `run`, and policies run only as the system. `ActorOf` gives a team-only decision a team member without narrowing, and `reporterOf` is the only place that derives a reporter. The read-model test sets up its data through `executeCommand` (Q3). `formRunner` is a real seam with two adapters: `formAction` bound to the session, and the tests' injected `currentPerson`.
