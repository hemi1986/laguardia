## Checked without findings
- **Module boundaries (ADR 0002):** the page data function composes the public queries of Repair (`triageList`, `openDefectCounts`) and Collection (`machineOverview`) through their `index.ts`, as the conventions require ("the page composes", ST-009). It imports no tables, and no machine IDs reach the rendered page.
- **Time on read (ADR 0002):** "waiting longer than 3 days" comes from `triageList(db, clock)`, which uses `elapsedMoreThanHours`. The page passes `systemClock` and the tests pass `fixedClock`. There is no `new Date()`.
- **Domain rules:** the dashboard only shows; returning to play goes through ST-012's status page and CMD-ChangeMachineStatus (HS-6, a manual policy). Defects on hold count as open (`state = 'open'`), as the defect lifecycle says. Retired machines are excluded by `machineOverview`.
- **Authorization / G11:** only `role === "technician"` gets the dashboard. Helpers keep the placeholder, as decided on 2026-10-15. Nothing new posts a form, so there are no new CSRF concerns. Museum numbers in links are `encodeURIComponent`-ed.
- **UX:** sections in the order G18 fixes, counts in words with a link instead of a repeated list (G5, G6, G6a, and the story's 2026-10-15 decision), the "nothing needs attention" sentence and the per-section empty sentences (G7), and one action per entry (G5). `CardTitle` renders `h2`, so the sections have headings.
- **Scenarios:** all 9 titles exist. The integration test runs green (7/7).
