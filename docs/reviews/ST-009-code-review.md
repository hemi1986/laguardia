## Resolution (implementer, 2026-10-02)

Findings of this review (#) and of the acceptance test (`ST-009-acceptance.md`, AT):

- **#1 major – fixed with the user.** The user decided the machine record's sections and their order (2026-10-02); they are in ST-009's Context and in the view's comment: retirement note, "Problem melden" (ST-015), details with their actions (ST-012, ST-034, ST-035, ST-011), open defects (ST-021), due maintenance (ST-047), status history, repair history (ST-033), files (ST-037), retiring (ST-039).
- **#2 / AT 1–2 – open question for ST-039.** Which status a retired machine's record shows (and whether retirement enters the status history) is a row in `OPEN_QUESTIONS.md`; not decided in code.
- **#3 – fixed.** The retirement note names who retired the machine: "Ausgemustert am … von Tom – Sold".
- **#4 – fixed.** `Retirement` is defined once (the value object, `register-machine.ts`), mapped from a row in one place (`retirementOf`); the page data replaces only `retiredBy` with a name.
- **#5 – fixed (comments).** `machineStatusHistory` stays – the ST-007 tests follow a machine's changes through it – with a comment saying so; `storedMachine`'s comment is current.
- **#6 – fixed.** The page test asserts every detail term and value, so it is checked in CI too, not only in the local browser test.
- **#8 – fixed.** **Status history** / "Status-Historie" is in `CONTEXT.md`; the heading comes from `terms`.
- **#9 – fixed.** The overview's entry links are always underlined.
- **AT 3 – fixed.** Long words wrap in the details and the history (`overflow-wrap: anywhere`, the value column may shrink); browser test with a 69-character location – fails without the fix.
- **#7 – skipped.** The `RM-MachineRecord` read-model test stays in `machine-overview.integration.test.ts`, which already has the isolated database and machine models it needs; revisit when the record gets more read-model tests.
- **#10 – not this story.** `src/proxy.ts` outside the boundary rule predates ST-009.
- **AT 4–6 – skipped as minors.** The "unbekannt" fallback (a deleted team member cannot happen – accounts are never deleted), the visitor redirect (the same `requireTeamMember()` as every team page, tested for the overview in ST-008), summer time (the Berlin formatting is `src/platform/time.ts`'s, tested there).
- **AT 7 – fine.** An unknown museum number answers with the message inside the team page.
